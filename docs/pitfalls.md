# 踩过的坑（都是真事故，照着躲）

## 视频一旦「经服务器」，方案就失去意义

- **Jellyfin 的 `/Videos/{id}/stream` 永远不会自己 302**，默认会读文件再转发。必须在 nginx 层用 map 拦下来
  并 `return 302`。验证方式：带 `Range` 请求那个 URL，返回 302 才对；返 200/206 就是在替客户端搬字节。
- 有人为了「先能播」把 OpenList 存储策略改成 `native_proxy`——那是把服务器的带宽和内存当转码机用。
  宁可暂时播不了，也别动 302。
- 播放地址写错端口同样致命：`https://host:443/dav` 写成 `:80` 再选 HTTPS，会在明文端口做 TLS 握手，
  播放器只报「网络异常」，服务端日志一条请求都没有。

## 命名与集号

- **别按固定体积砍「小文件」**：短剧单集只有十几 MB，一刀切 50MB 会把整部剧切光。用「该剧中位体积的 8%」自适应过滤。
- **发布者绕审核会把集号拆开**：`1@8&4` = 184、`9！7` = 97。要先把画质标记（`2160P`/`4K`）与年份剔掉再抽数字，
  否则 `2026` 会被当集号；`xx.mp4.mp4` 这种重复后缀只能算一次，不然 `1@8&4.mp4.mp4` 会读成 1844。
- **标题里的集数不能信**：写「更新至 161 集」往往只有最后 1–3 集（滚动窗口）。判断完整性要看展开子目录后的实际文件名。
- **给目录挑 TMDB 条目，判据是「本地最大集号 ≤ TMDB 总集数」**，不是「文件数最接近总集数」。
  后者会把正传挑成番外/合集篇/剧场版。
- `.nfo` 里**别写 `<title>`**：写了 Jellyfin 就锁死本地标题，不去 TMDB 取真实集名。

## 同步与缓存

- **新转存的目录 OpenList 可能立刻看不见**（缓存）。生成 strm 前先 `POST /api/fs/list` 带 `"refresh": true` 刷父目录，
  否则脚本会「静默跳过」，看起来像没配规则。
- **`gen_strm_map.py` 必须排在 Jellyfin 扫库之后**：它靠 `/Items` 拿 item id。扫库前跑只会写回旧条目数，新片播不了。
- 查「新片有没有入库」别用 `Path` 过滤来源目录名：strm 条目的 `Path` 是 `/媒体库/电影/<片名 (年)>/<片名 (年)>.strm`，
  不含网盘那边的目录名，按来源名过滤永远 0 命中（会误判成没入库）。
- OpenList 会把新目录缓存成 0 项；播放器里看不到时先刷新缓存再怀疑别的。

## 转存

- 官方接口的 `saveas-update` 是**增量**（不删旧、存回原目录）——这是路径稳定、strm 不必每轮重建的根本。
  换成「先删后传」的工具，所有 URL 会立刻失效。
- 同名文件夹会让某些实现「静默不新增」：判据永远是「逐文件比对分享清单 vs 网盘实际文件」，不是「有同名文件夹就断定失败」。
- 分享链接会死（`分享地址已失效` / `好友已取消了分享` / `分享者用户封禁`），标题写「全集」的往往是最先死的那批。

## 资源紧张时的表现

- 单核小机器上，扫库/转存会让 load 短时冲到 1.0，内存靠 swap 兜住（1.6G 内存实测长期用掉 1.1G + 1G swap）。
  这时**别急着加钱升级**：视频不过服务器，加核加内存对「看剧卡不卡」几乎无感；先确认不是 OOM 杀进程。
- OpenList 反复 401 会触发登录限流，之后全变 429，播放器显示成「网络异常」。401 = 账号密码错；429 = 被限流，
  重启服务清零后再试，别连着点重试。

## 别把「手工维护的数据」放在会被清理的缓存目录

映射表（`tmdb_final.json`，18 条手工配好的 TMDB 条目）最初放在 `~/.hermes/cache/scratch/`，
而那个目录是 agent 的临时区、**闲置 24 小时的条目会被自动 prune**——文件平时只被读、mtime 不变，
于是某天 cron 直接 `FileNotFoundError`，整条入库链停摆，而且报错只是一行 traceback，看不出根因。

- 手工数据一律放**状态目录**（本仓库默认 `~/.cache/strm/state/`，生产机放 `/root/.state/`），
  别放 `cache/`、`tmp/`。
- 映射表丢了能救：媒体库里每个剧都有 `tvshow.nfo`，里面的 `<uniqueid type="tmdb">` 就是条目 id，
  按它重新拉一次 TMDB 即可重建（季/集数从 TMDB 读，比从生成的 strm 反推更准）。
- 恢复后的验收标准：`strm_sync.py --dry` 输出应回到 `新增 0 / 变化 0`，
  且临时构建的文件数与媒体库一致；对不上就说明还有目录没回到映射表（漏一条就会少几个文件）。
